# Monotonic Clock Timing and Foreground Service Architecture

We accumulate `Effective Duration` and `Paused Duration` using `SystemClock.elapsedRealtime()` monotonic intervals rather than counting `HeartRateSample` rows or calculating wall-clock diffs (`System.currentTimeMillis()`). Wall-clock time is vulnerable to NTP network adjustments, manual time changes, and timezone shifts, while coroutine delay timers drift over multi-hour runs. The Android Foreground Service (`foregroundServiceType="connectedDevice"`) is active only during an open Session, holds a `PARTIAL_WAKE_LOCK` exclusively while in `Recording` state, and returns `START_NOT_STICKY`. State and telemetry coordinate via a singleton `SessionRepository` driving a reactive `StateFlow`, eliminating fragile `ServiceConnection` Binder IPC while ensuring zero-drift timing across screen rotations and background execution.
